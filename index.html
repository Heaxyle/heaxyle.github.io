Drake Arena

A real-time web app driven by live Twitch chat events, tested like a production feature.

Viewers create a drake, pick one of six elements and join a ranked queue. Turn-based fights then play out on stream on their own: crits, armor, twelve buffs and debuffs, class ultimates and a sudden-death phase. It is a single HTML file with no build step and no backend, in English and Ukrainian. The code is written with Claude Code; I own the game design, the balance tuning, the bug reviews and the test plan.

The bug the tests missed

Every automated check was green while a title badge sat 5 px low and got clipped on every fighter card. Manual review of the CI screenshots caught it; one line of CSS fixed it. The lesson went into the test docs: green automation doesn’t prove readability.

Read it as filed: the bug report ↓
drake-arena · UI · overlay Fighter-card title badge is clipped at the bottom edge
Severity
Minor (cosmetic), Priority: Medium. Visible on every fighter card, on stream, for the whole fight.
Environment
Chromium, 1920×1080 overlay (OBS browser-source size). English and Ukrainian.
Found by
Manual review of the CI layout-test screenshots. All automated checks were green.
Steps
  1. Open showcase/index.html.
  2. In the chat simulator, register two drakes (!drake red, !drake blue) and give each a title with !title.
  3. Start a fight (!queue for both, or 🎬 Demo).
  4. Look at the title badge under each fighter’s name once the cards render.
Expected
The badge sits fully inside the name block, with its bottom border visible.
Actual
The badge’s bottom edge is cut off by about 5 px; the bottom border and the lower part of the text are hidden.
Root cause
The badge was an inline-block sitting on the text baseline, which put it ~5 px low inside its fixed-height, overflow: hidden container.
Fix
vertical-align: top on .fighter-title-badge. One line of CSS.
Follow-up
Added to the test docs: green automation doesn’t prove readability. Screenshots are reviewed after every visual change, and CI uploads them on every run.

QA Knowledge Assistant

A local retrieval (RAG) tool that answers questions from test plans, specs and past bug reports, and cites the source file on every answer. It runs on your own machine, so the documents never leave it. Built with AI assistance for a friend’s support team, then rebuilt for QA docs.

Two searches run side by side: vector search for meaning, and keyword search for exact hits like feature names, ticket IDs and error codes. The results are merged and reranked before the model sees them. Answers come back in three parts: known coverage from the docs, suggested edge cases, and a draft bug report when one fits.

Code excerpt · the hybrid retriever

class NativeHybridRetriever(BaseRetriever):
    """Merges vector + BM25 results, then reranks before handing to the LLM."""
    def _get_relevant_documents(self, query, *, run_manager=None):
        vec_docs = self.vector_retriever.invoke(query)
        bm25_docs = self.bm25_retriever.invoke(query)

        combined = {d.page_content: d for d in vec_docs + bm25_docs}
        unique_docs = list(combined.values())

        if self.reranker and unique_docs:
            return self.reranker.compress_documents(unique_docs, query)[:self.top_n]
        return unique_docs[:self.top_n]
